Root of the chessclub-web Flask application — a web portal for visualizing Chess.com club statistics with a background sync worker, SQLAlchemy persistence, and DB-first route pattern.

## Summary

- `run.py` — Development server entry point; calls `create_app()` and runs Flask in debug mode.
- `config.py` — Application configuration loaded from environment variables (Flask, OAuth, server cookies, sync interval, database URI).
- `pyproject.toml` — Project metadata and Ruff linter/formatter configuration (target Python 3.11, Google-style docstrings).
- `requirements.txt` — Python dependencies: Flask 3.0+, Flask-SQLAlchemy, python-dotenv, requests, APScheduler, gunicorn, and the `chessclub` library (installed from GitHub).
- `Dockerfile` — Multi-stage Docker build: `base` (Python 3.11-slim), `dev` (Flask dev server), `prod` (gunicorn WSGI).
- `docker-compose.yml` — Base Compose service definition with volume for DB data and club list.
- `docker-compose.override.yml` — Dev overrides: bind-mount source, disable .venv overlay, enable debug.
- `.env.example` — Template for local secrets (SECRET_KEY, OAuth client ID, server cookies, admin password).
- `.gitignore` — Ignores venv, caches, instance data, .env, .agents, .memory.
- `.dockerignore` — Files excluded from Docker build context.
- `AGENTS.md` — Repository instructions for AI coding agents.
- `CHANGELOG.md` — Keep a Changelog format version history (current: 0.1.3).
- `CONTRIBUTING.md` — Branch model (develop/main), Ruff workflow, style conventions.
- `LICENSE` — MIT License.
- `README.md` — Project overview, quick start, architecture summary, env vars reference.
- `SECURITY.md` — Security policy, supported versions, reporting process.
- `watched_clubs.json` — JSON list of club slugs to sync (e.g., `["clube-de-xadrez-de-jundiai"]`).
- `app/` — Flask application package (templates, blueprints, models, services, sync).
- `docs/` — Architecture and caching documentation.
- `instance/` — Runtime data directory (SQLite DB); gitignored.
- `.venv/`, `__pycache__/`, `.ruff_cache/` — Generated/venv directories; gitignored.
- `.agents/` — Agent Starter Kit orchestration framework; gitignored.
- `.memory/` — Agent long-term memory; gitignored.

## Constraints

- MUST NOT commit `.env`, any `*.db` file, or `instance/` contents.
- MUST run `ruff check .` and `ruff format --check .` before committing.
- MUST use Python 3.11+ syntax (type annotations with `X | Y` union syntax).
- MUST NOT modify `.agents/` directory contents (it is gitignored and managed externally).

## Guidance

- SHOULD use Docker Compose for development (`docker compose up`) and production (`docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d`); a prod override file must be created first.
- Config `SECRET_KEY` SHOULD be a strong random value in production (`secrets.token_hex(32)`).
- Admin panel SHOULD be disabled (`ADMIN_PASSWORD=""`) unless needed.

## Error Handlers

Custom error handlers are registered in `app/__init__.py`:
- `404` → `templates/errors/404.html`
- `403` → `templates/errors/403.html`
- `500` → `templates/errors/500.html`

## Health Endpoint

`GET /health` returns JSON `{"status": "ok", "timestamp": "...", "sync": {}}`.
Registered in `app/__init__.py`; does not require authentication.
