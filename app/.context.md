The main Flask application package containing blueprints, ORM models, service wrappers, the sync worker, and all Jinja2 templates. This is where every execution path begins and ends.

## Summary

- `__init__.py` — Flask application factory (`create_app()`): initializes SQLAlchemy, registers Jinja2 filters (`ts_to_date`, `ts_to_datetime`, `country_flag`), injects auth context processor, registers four blueprints, and starts the APScheduler sync scheduler.
- `extensions.py` — Single shared `SQLAlchemy()` instance used by all modules.
- `models.py` — Six SQLAlchemy ORM models: `ClubModel`, `MemberModel`, `TournamentModel`, `TournamentResultModel`, `GameModel`, `ClubRecordModel`. Each maps 1:1 to a chessclub library dataclass.
- `chess_service.py` — Wrapper around `chessclub` library: provides `make_client()` (credential resolution: server cookies + OAuth > OAuth only > public only) and `is_authenticated()`. Includes `_SessionOAuthProvider` for session-backed OAuth.
- `db_service.py` — Data access layer: write functions (called by sync worker) and read functions (called by routes). Read functions return chessclub library dataclass instances. Computed aggregates: leaderboard, matchups, attendance, rating history.
- `club.py` — Club blueprint (`/`): home page, search, and seven club detail pages (overview, members, tournaments, leaderboard, matchups, attendance, records). All follow DB-first pattern with chessclub library fallback.
- `player.py` — Player blueprint (`/player/<username>/rating-history`): rating evolution across club tournaments. DB-first with library fallback.
- `auth.py` — Auth blueprint (`/auth`): OAuth 2.0 PKCE login/callback/logout, and setup page for server cookie credentials.
- `admin.py` — Admin blueprint (`/admin`): login, dashboard with sync status, watched clubs management (add/remove), manual sync triggers (Phase 1 and Phase 2).
- `sync.py` — Background sync worker: APScheduler-based periodic sync (Phase 1: light data) and manual per-club game archive sync (Phase 2: game archives + records). Threading with daemon threads. Real-time status tracking via module-level `sync_status` dict.
- `templates/` — Jinja2 templates (13 files in 4 subdirectories).
- `static/` — Static assets (custom CSS).

## Constraints

- MUST NOT call the chessclub library for watched clubs — DB-first routes must only use `db_service` if the club is in the database.
- MUST NOT expose server cookies (`CHESSCOM_SERVER_ACCESS_TOKEN`, `CHESSCOM_SERVER_PHPSESSID`) to client-side code.
- APScheduler MUST NOT start in the Flask reloader child process (guarded by WERKZEUG_RUN_MAIN check).

## Guidance

- Read functions SHOULD return `None` when no data is found (not empty lists) so callers can distinguish "no data" from "empty result set."
- Templates SHOULD remain data-source agnostic — they receive the same chessclub dataclass instances regardless of whether data came from DB or library.
- Exception handling SHOULD catch specific exception types (`ChessclubError`, `requests.RequestException`, etc.) in routes to prevent internal details from leaking to the user.
